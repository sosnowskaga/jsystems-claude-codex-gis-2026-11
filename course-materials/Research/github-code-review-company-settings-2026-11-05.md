# Konfiguracja review w firmie: ChatGPT Business i GitHub

Instrukcja do samodzielnego skonfigurowania dostępu. Stan dokumentacji: 5.11.2026. Ustawień kont ani organizacji nie zmieniano. Własny fork i repo firmy mają różnych właścicieli; publiczność repo nie nadaje uprawnień administracyjnych.

| Kto | Za co odpowiada |
|---|---|
| ChatGPT Business Owner/Admin | Dostęp workspace do aplikacji i limity dodatkowego usage; zakup/reload kredytów tylko Owner |
| GitHub organization owner | Instalacja i zakres aplikacji w organizacji, OAuth, polityki i źródło billingów Copilot |
| GitHub repo admin | Ruleset repo; dodanie administrowanego repo do zatwierdzonej instalacji, jeśli polityka pozwala |
| Członek workspace z GitHub push/admin w repo | Własne połączenie i ustawienia Codex review tego repo |
| Właściciel osobistego forka | Konfiguracja własnego konta i forka; nie administruje repo prowadzącego |

**ChatGPT Business i GitHub Copilot Business są oddzielnymi produktami.** Uprawnienia administratora jednego nie nadają uprawnień w drugim.

## 1. Administrator ChatGPT Business

1. **Potwierdź produkt i konto.** Codex Cloud jest dostępny w Business, zależnie od rolloutów i ustawień workspace. Działający CLI nie potwierdza jeszcze integracji cloud-review. [OpenAI: plany i dostęp Codex](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan).
2. **Sprawdź dostęp do aplikacji:** [Admin Console](https://admin.openai.com/) -> właściwy workspace **Business -> Plugins -> plugin zawierający GitHub -> dostęp do dołączonej aplikacji**. Zachowana starsza ścieżka to **Workspace settings -> Apps** lub **Plugins -> Manage Legacy Apps**. Business ma aplikacje domyślnie włączone. Jeśli GitHub jest wyłączony, Owner/Admin może udostępnić go w tym miejscu zgodnie z polityką firmy i sprawdza zapisany stan po odświeżeniu. Decyzja dotyczy całego workspace, nie wybranych ról; nie nadaje sama dostępu do repo ani nie włącza review. [OpenAI: kontrolki Business](https://help.openai.com/en/articles/11509118-admin-controls-security-and-compliance-for-plugins-and-apps).
3. **Sprawdź kontrolę kosztu:** **Workspace settings -> Billing**, albo **Admin Console -> Business workspace -> Billing**. Owner/Admin może ustawić miesięczny limit przy typie seata (**Add**) i **Per user override -> Manage -> Add**. Zakupy i **Automatic reload** należą do Ownera. Standard/Premium najpierw wykorzystują usage wliczone w seat, później kwalifikujące użycie może zużywać kredyty workspace. To nie kredyty API ani stała liczba recenzji. Jeśli Owner korzysta z Automatic reload, ustawia **Monthly recharge limit**; pusty limit pozwala na nieograniczone automatyczne zakupy. Pokaz istniejącego dostępu nie wymaga włączania reloadu ani zakupu. [OpenAI: limity i billing Business](https://help.openai.com/en/articles/20001155-managing-credits-and-spend-controls-in-chatgpt-business).

**Nie kopiuj ekranu Enterprise do Business.** Oficjalny artykuł RBAC nie wymienia Business w dostępności custom roles. Nie twórz Custom role ani nie przyjmuj Enterprise-only defaultu Cloud jako reguły Business. Publiczna dokumentacja nie ustala jednej uniwersalnej ścieżki osobnych przełączników Codex Local/Cloud dla wszystkich Business workspace. Brak danej kontrolki nazwij wprost i sprawdź z administratorem/supportem. [Zakres RBAC](https://help.openai.com/en/articles/11750701-managing-feature-access-with-role-based-access-control-in-chatgpt), [Codex: sekcja Enterprise setup and controls](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan).

## 2. GitHub: administrator organizacji firmowej

0. **Jeśli aplikacji jeszcze nie ma:** otwórz [instalację ChatGPT Codex Connector](https://github.com/apps/chatgpt-codex-connector/installations/select_target), wybierz właściwe konto/organizację i repo pilota, przeczytaj uprawnienia oraz potwierdź instalację. Osoba bez praw instalacji wysyła dozwoloną prośbę do org ownera zamiast obchodzić ograniczenie. Dotyczy też pierwszej instalacji na osobistym forku. [GitHub: instalacja i role](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party).
1. **Sprawdź instalację i repo:** avatar -> **Your organizations -> organizacja: Settings -> Third-party Access -> GitHub Apps -> ChatGPT Codex Connector -> Configure -> Repository access**. Jeśli jest **All repositories**, pozostaw ten zakres. Jeśli jest **Only select repositories**, dodaj repo pilota bez usuwania pozostałych i wybierz **Save**. Owner zarządza instalacją; repo admin może mieć możliwość dodania swojego repo do istniejącej zatwierdzonej instalacji, zależnie od polityki. [GitHub: zmiana instalacji](https://docs.github.com/en/apps/using-github-apps/reviewing-and-modifying-installed-github-apps), [wymagane role](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party).
2. **Jeśli pojawia się żądanie OAuth:** członek autoryzuje aplikację i składa prośbę o dostęp organizacji; org owner zatwierdza: **Organizations -> organizacja -> Settings -> Third-party Access -> OAuth app policy -> aplikacja: Review -> Grant access**. To osobna decyzja ownera, nie powód do wyłączenia polityki całej organizacji. [GitHub: approval OAuth](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization).
3. **Jeśli firma ma SSO - krok członka organizacji:** użytkownik otwiera [GitHub SSO settings](https://github.com/settings/sso), przy organizacji wybiera **Sign in** i ponawia autoryzację. SSO GitHub nie jest SSO OpenAI. [GitHub: autoryzacja aplikacji z SSO](https://docs.github.com/en/enterprise-cloud@latest/authentication/authenticating-with-single-sign-on/authorizing-an-app-for-single-sign-on).

Dla **osobistego forka** właściciel sprawdza: avatar -> **Settings -> Integrations -> Applications -> Installed GitHub Apps -> Configure**. Wybiera swoje repo, nie repo prowadzącego. [GitHub: konto osobiste i organizacja](https://docs.github.com/en/apps/using-github-apps/reviewing-and-modifying-installed-github-apps).

## 3. Członek workspace: GitHub i Codex Code Review

1. Użytkownik wybiera właściwe konto/workspace i **Sign in with ChatGPT** w kliencie Codex ([dostęp](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)). Następnie we właściwym workspace otwiera **Settings -> Plugins -> GitHub** lub plugin zawierający tę aplikację. Zaloguj się do swojej tożsamości GitHub, autoryzuj dozwolony zakres i wybierz repo. Zmiany listy repo mogą pojawić się po kilku minutach. Jeśli repo firmy jest niedostępne, wróć do administratora z punktu 2. [OpenAI: połączenie GitHub](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt).
2. Otwórz **[Codex settings -> Code review](https://chatgpt.com/settings/code-review)**. Wybierz konkretne repo, potem **Review code -> Automatic review**, jeśli konfigurujesz automat. Wymagane są połączona tożsamość oraz odpowiednie uprawnienia GitHub push/admin. Osobiste **Personal preferences -> Automatic review -> Review trigger** dotyczą własnych PR. [OpenAI: konfiguracja review](https://learn.chatgpt.com/docs/third-party/github).
3. Przetestuj jedno małe PR: komentarz **`@codex review`**, następnie sprawdź rzeczywisty wynik i SHA. Sekcja **`## Code Review Rules` w pliku `AGENTS.md`** określa kryteria; nie instaluje bota i nie włącza triggera. [OpenAI: użycie i instrukcje](https://learn.chatgpt.com/docs/third-party/github).

**To nie są dwie niezależne instalacje aplikacji GitHub.** Oficjalny artykuł połączenia ChatGPT kieruje do **ChatGPT Codex Connector**, aplikacji @openai obsługującej ChatGPT i Codex. Wspólna aplikacja nie oznacza jednak, że każdy członek ma aktywne połączenie, odpowiedni workspace i włączone review. [OpenAI: połączenie](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt), [GitHub App](https://github.com/apps/chatgpt-codex-connector).

Dokumentacja pokazuje zakres **All PRs** i **Follow personal preferences**, lecz nie wylicza wszystkich etykiet menu triggerów ani reguły obciążania quota dla każdego wariantu fork/autor. Nie przenoś opcji z Security Review do zwykłego Code Review. Na pierwszym pilocie użyj jednej tożsamości workspace jako autora PR, konfigurującego i zamawiającego review. Nie rozszerzaj od razu na All PRs/cudze forki przed potwierdzeniem konta i usage. Dokument opisuje repo Automatic review i osobiste preferencje; nie zakładamy istnienia dwóch osobnych przełączników ręczne/automatyczne ani nie opisujemy fikcyjnego Save w Codex. Odśwież wybrany ekran i potwierdź zapisany stan. GitHub Code Review i lokalne review używają różnych kategorii usage. [Ustawienia Codex](https://learn.chatgpt.com/docs/third-party/github), [usage](https://learn.chatgpt.com/docs/pricing).

## 4. GitHub Copilot Business: oddzielna konfiguracja

- **Org owner:** **Organizations -> organizacja -> Settings -> Code, planning, and automation -> Copilot -> Policies**; włącz dostępność Copilot code review na poziomie organizacji. Dostęp konkretnej osoby wynika osobno z licencji lub dozwolonego płatnego usage. Polityka enterprise może być nadrzędna. [Polityki organizacji](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-organization/manage-policies).
- **Repo admin:** **Settings -> Rulesets -> Rulesets -> New ruleset -> New branch ruleset -> Ruleset name -> Active -> Add target -> Include default branch -> Automatically request Copilot code review -> Create**. Na pierwszy przebieg nie włączaj automatycznego review każdego pushu/draftu. [Konfiguracja](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-code-review).
- **Org owner:** **Settings -> Copilot -> Code review**: sprawdź effort, jego maksimum oraz źródło billingów **Member / Organization**. Organization wymaga AI credits paid usage; dostęp/licencja jest osobnym warunkiem. [Ustawienia firmy](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-code-review).
- **Użytkownik:** **Copilot settings -> Code review -> Automatic Copilot code review**, albo w PR **Reviewers -> Copilot**. Osobista automatyka i ruleset działają niezależnie; osobista automatyka jest niedostępna dla managed user accounts. Copilot Free nie zawiera tej funkcji; dostęp nielicencjonowanych członków wymaga osobnej polityki płatnego usage. [Konfiguracja użytkownika](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-code-review), [dostęp i koszty](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review).

## 5. Gdy uczestnik nie jest administratorem

Nie prosi o cudzy token lub Ownera na czas ćwiczenia. Przekazuje IT: właściwy workspace Business, GitHub organizację, jedno repo pilota, potrzebę Codex Cloud/Code Review, aplikację **ChatGPT Codex Connector**, minimalny zakres repo i właściciela kosztów. Dla Copilot osobno licencja/polityka review/ruleset. Nie przenosi kodu firmy do prywatnego workspace jako obejścia.

Na własnym forku ustawienia wykonuje jego właściciel. Dla fork PR do firmy konfiguruje się repo **bazowe firmy**. Uprawnienia fine-grained PAT tylko do forka nie pozwalają publikować komentarzy w upstream; pełne ćwiczenie i wariant przeglądarkowy opisuje [fork -> PR -> odpowiedź na review](github-fork-pr-review-workshop-2026-11-05.md).

## Pilot kończy się dowodem

Jeden właściciel, jedno repo, jeden reviewer, jeden konkretny SHA. Po zapisaniu wybranych ustawień utwórz/wybierz PR i zamów review. Sprawdź faktyczny wynik oraz poprawkę i aktualny head. Sam request, emoji, brak uwag lub zielony job nie są potwierdzeniem pełnego review. Dopiero po takim pilocie rozszerzaj konfigurację na kolejne repo zgodnie z polityką firmy. Jeśli wyczerpana jest kategoria cloud Code Review usage, a ogólny usage pozostał, pokaż lokalne review, które zużywa ogólny usage; nie aktywuj nowego źródła kosztów w ciemno.
